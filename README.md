# ❄️ NixOS Fleet

> Flake-based NixOS with Home Manager. Four hosts — **titan**, **ghost**, **minimal**, **server** — built from focused, single-purpose modules.

**Design rule:** every module does exactly what its filename says. If a module touches multiple unrelated systems, it gets split.

---

## Quick Reference

```bash
cd ~/.config/nixos

# Dry-run a host
nixos-rebuild build --flake .#titan

# Activate on current machine
sudo nixos-rebuild switch --flake .#titan

# Update inputs and rebuild
nix flake update
sudo nixos-rebuild switch --flake .#titan

# Format the repo
nix fmt
```

## Architecture

Three layers, no mixing:

```
┌──────────────────────────────────────────────────────────────────────┐
│  HOST          hosts/<host>/default.nix                              │
│  ├── hardware-configuration.nix   (generated, per-machine)           │
│  ├── sensors.nix                  (host-specific hardware quirks)    │
│  └── imports → system-core.nix + system-desktop.nix (optional)     │
│                                                                      │
│  SYSTEM-CORE   system-core.nix                                       │
│  └── system-level/                                                   │
│      ├── boot.nix, networking.nix, firewall.nix                      │
│      ├── locale.nix, logging.nix, maintenance.nix                      │
│      ├── programs.nix, nix-settings.nix                              │
│      └── hardening, boot, nix daemon, etc.                           │
│                                                                      │
│  SYSTEM-DESKTOP system-desktop.nix                                   │
│  └── system-level/                                                   │
│      ├── desktop.nix, audio.nix, bluetooth.nix                        │
│      ├── theming.nix, flatpak.nix, nvf.nix                           │
│      ├── kanata.nix, virtualization.nix, printing.nix                │
│      └── podman.nix, avatar.nix                                     │
│                                                                      │
│  USER          user-level/home-manager/stefan-hacks/                │
│  ├── programs/  →  bash, kitty, starship, atuin, helix, etc.         │
│  └── gnome/     →  dconf settings (generated by nix-my-gnome)      │
└──────────────────────────────────────────────────────────────────────┘
```

| Layer | Responsibility |
|---|---|
| **Host** | Hardware, LUKS, GPU drivers, hostname, per-host imports. Thin wrapper. |
| **System Core** | Universal OS settings imported by ALL hosts (boot, networking, hardening, nix, maintenance). |
| **System Desktop** | GUI-only modules imported by desktop hosts (GNOME, audio, flatpak, theming, podman). |
| **User** | Dotfiles, program configs, shell aliases, GNOME dconf, ICC color profiles. Declarative via Home Manager. |

**Split rule:** `minimal` and `server` import only `system-core.nix`. `ghost` and `titan` import both.

## Installing from NixOS Minimal ISO (Blank SSD)

### 1. Boot the installer

```bash
# Set a password for SSH access
passwd

# Identify your target disk
lsblk
```

### 2. Partition and format with Disko

Each host has a `disko-config.nix`. Edit the `device` line to match your real disk:

```bash
nano hosts/titan/disko-config.nix
# Change: device = "/dev/nvme0n1";
```

Uncomment the disko imports in the host's `default.nix`:

```bash
nano hosts/titan/default.nix
# Uncomment these two lines:
# "${builtins.fetchTarball "https://github.com/nix-community/disko/archive/master.tar.gz"}/module.nix"
# ./disko-config.nix
```

Run disko (from the installer):

```bash
sudo nix --experimental-features "nix-command flakes" run \
  github:nix-community/disko -- \
  --mode destroy,format,mount ./hosts/titan/disko-config.nix
```

> ⚠️ **This erases the entire target disk.**

### 3. Generate hardware config

```bash
sudo nixos-generate-config --no-filesystems --root /mnt
```

### 4. Copy configuration and install

```bash
sudo mkdir -p /mnt/etc/nixos
sudo cp -r ~/.config/nixos/* /mnt/etc/nixos/
sudo cp /mnt/etc/nixos/hardware-configuration.nix /mnt/etc/nixos/hosts/titan/
sudo nixos-install --flake /mnt/etc/nixos#titan
```

### 5. Set password and reboot

```bash
sudo nixos-enter --root /mnt
passwd stefan-hacks
exit
reboot
```

### 6. Post-install

After first boot, re-comment the disko lines in `hosts/titan/default.nix`. From now on:

```bash
cd ~/.config/nixos
sudo nixos-rebuild switch --flake .#titan
```

## Using This Repo in an Existing Flake + Home Manager Setup

You don't have to adopt the whole repo. Import only the pieces you need.

### Option A: Import system modules into your own flake

In your `flake.nix`:

```nix
{
  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-26.05";
  inputs.home-manager = {
    url = "github:nix-community/home-manager/release-26.05";
    inputs.nixpkgs.follows = "nixpkgs";
  };

  outputs = { self, nixpkgs, home-manager, ... }:
    let
      system = "x86_64-linux";
    in {
      nixosConfigurations.myhost = nixpkgs.lib.nixosSystem {
        inherit system;
        modules = [
          home-manager.nixosModules.home-manager
          {
            home-manager.useGlobalPkgs = true;
            home-manager.useUserPackages = true;
            home-manager.users.stefan-hacks = {
              imports = [
                ./user-level/home-manager/stefan-hacks/default.nix
              ];
            };
          }
          # Pick and choose system modules:
          ./system-level/boot.nix
          ./system-level/networking.nix
          ./system-level/audio.nix
          ./system-level/locale.nix
          # ...etc
        ];
      };
    };
}
```

### Option B: Import only Home Manager user config

If you already have a working NixOS system and just want the user dotfiles:

```nix
# In your existing home-manager configuration
{
  imports = [
    # Pick individual modules:
    ./nixos-repo/user-level/home-manager/stefan-hacks/programs/bash.nix
    ./nixos-repo/user-level/home-manager/stefan-hacks/programs/aliases.nix
    ./nixos-repo/user-level/home-manager/stefan-hacks/programs/kitty.nix
    ./nixos-repo/user-level/home-manager/stefan-hacks/programs/starship.nix
    # ...etc
  ];
}
```

> **Note:** `aliases.nix` depends on `lib` (for `lib.genAttrs` and `lib.foldl'`). `bash.nix` depends on `pkgs` (for zoxide, blesh). Ensure your HM config provides these.

### Option C: Add as a flake input

```nix
{
  inputs.stefan-nixos = {
    url = "github:stefan-hacks/nixos-config"; # or path:/home/.../.config/nixos
    flake = false;
  };

  outputs = { self, nixpkgs, home-manager, stefan-nixos, ... }:
    let
      system = "x86_64-linux";
    in {
      nixosConfigurations.myhost = nixpkgs.lib.nixosSystem {
        inherit system;
        modules = [
          home-manager.nixosModules.home-manager
          {
            home-manager.useGlobalPkgs = true;
            home-manager.useUserPackages = true;
            home-manager.users.stefan-hacks = {
              imports = [ (stefan-nixos + "/user-level/home-manager/stefan-hacks/default.nix") ];
            };
          }
          (stefan-nixos + "/system-level/boot.nix")
          (stefan-nixos + "/system-level/networking.nix")
          # ...etc
        ];
      };
    };
}
```

## Shell Stack

All shell tools are installed via Home Manager (not system-level) to control init order relative to ble.sh:

| Tool | Role | Integration |
|------|------|-------------|
| **ble.sh** | Bash line editor + vi mode | Sourced in `bashrcExtra`. `unset -f read` removes its read wrapper to prevent conflicts with carapace/fzf. |
| **zoxide** | Smart cd | `zoxide init bash` in initExtra (order 1950) |
| **atuin** | Shell history | `atuin init bash` AFTER `ble-attach` (order 2100). `ATUIN_CONFIG_DIR` exported for non-login shells. |
| **carapace** | Arg completion | `carapace _carapace bash` in initExtra |
| **starship** | Prompt | `starship init bash` in initExtra, guarded by `TERM != "dumb"` |
| **fzf** | Fuzzy finder | `fzf --bash` in initExtra |

> **Why HM, not system?** System-level packages insert init snippets into `/etc/bashrc` in unpredictable order. HM gives explicit control via `bashrcExtra` → `initExtra` with `lib.mkOrder`.

## Key Design Decisions

| Decision | Rationale |
|---|---|
| **Single-purpose modules** | A module named `audio.nix` only touches audio. No kitchen-sink files. |
| **Flakes** | Reproducible inputs with lockfile. All hosts share one `flake.nix`. |
| **Home Manager** | Declarative per-user config. Clean separation from system modules. |
| **Stable-first** | `nixpkgs` and `home-manager` track 26.05. GUI apps needing newer versions use flatpak. |
| **nvf (not LazyVim)** | Declarative Neovim with native Nix LSP/treesitter. No runtime Mason downloads. |
| **ble.sh + `unset -f read`** | ble.sh provides vi mode and syntax highlighting, but its `read` wrapper breaks carapace/fzf. Removing the wrapper fixes this. |
| **All shell tools in HM** | atuin, zoxide, carapace, starship, blesh are all user-level to avoid init-order conflicts. |
| **nix-my-gnome for dconf** | GNOME settings are generated from a live dconf dump, not hand-edited. Reproducible and version-controlled. |
| **KDL for complex configs** | Zellij and Kanata use raw KDL instead of Nix attrset serialization for readability. |
| **System split: core vs desktop** | `minimal`/`server` import only `system-core.nix`. `ghost`/`titan` import both. Eliminates desktop bloat on headless hosts. |
| **Flake-based auto-upgrade** | `system.autoUpgrade.flake` with `--update-input nixpkgs` replaces deprecated channel-based upgrades. |
| **Registry pinning** | `nix.registry.nixpkgs.flake = inputs.nixpkgs` pins `nix run nixpkgs#foo` to the exact locked nixpkgs. |
| **Declarative containers** | Podman containers (Debian, Rocky Linux) declared in Nix for reproducible local dev environments. |
| **ICC profiles in repo** | GNOME color calibrations stored per-host under `assets/icc/<host>/` and linked via Home Manager. |

## Terminal Colorization

All terminal output is colorized with **context-aware** tools (not generic rainbow prettifiers). Each tool understands the syntax or semantics of what it colors:

### grc — System Command Output

Regex-based colorization for 50+ commands. Examples:

```bash
df -h                    # disk usage with colored thresholds
du -sh *                 # directory sizes colorized
ip addr                  # network interfaces with colored IPs
ping 8.8.8.8             # latency colorized
ps aux                   # processes with colored CPU/memory
journalctl -u sshd       # logs with colored severity levels
systemctl status sshd    # service status with colored states
iptables -L              # firewall rules colorized
netstat -tlnp            # ports with colored states
ss -tlnp                 # sockets with colored states
traceroute google.com    # hop colors by latency
mount                    # mount points colorized
gcc main.c               # compiler errors in red, warnings in yellow
make                     # build output colorized
lsmod                    # kernel modules colorized
env                      # environment variables colorized
sysctl -a                # kernel parameters colorized
iostat 1 5               # I/O stats colorized
vmstat 1 5               # memory stats colorized
```

### bat + bat-extras — File Viewing & Search

Syntax-highlighting for any source file, with Catppuccin-Mocha theme:

```bash
bat script.py            # Python syntax highlighting
bat --diff file1 file2   # Diff with syntax highlighting
man ssh                  # Man pages with syntax highlighting (batman)
g docker                 # Help output colorized (bathelp)
grep -r TODO src/        # Grep with syntax highlighting (batgrep)
diff -u a.txt b.txt      # Diff with syntax highlighting (batdiff)
watch -n1 'cat log'      # Auto-refresh with highlighting (batwatch)
```

### delta — Git Diffs

Syntax-aware diff pager with side-by-side support:

```bash
git diff                 # colored by filetype, line numbers, decorations
git log -p               # patch view with syntax highlighting
git show HEAD            # commit diff with highlighting
git diff --staged        # staged changes with color
git merge conflict       # diff3 conflict style with highlighting
```

### ccze — Log Files

Colorizes log files by severity (ERROR red, WARN yellow, INFO green):

```bash
logs                     # alias: ccze -A (generic log colorizer)
syslog                   # system logs via ccze
dmesg                    # kernel ring buffer colorized
cat /var/log/nginx/*.log | ccze -A
journalctl --no-pager | ccze -A
```

### glow — Markdown

Renders markdown files in the terminal:

```bash
md README.md             # alias for glow README.md
md                       # interactive markdown browser
```

### fx — JSON

Interactive JSON viewer with color and tree navigation:

```bash
cat data.json | fx       # interactive tree with colors
curl -s api.github.com/users/octocat | fx
```

### source-highlight — Source Code Cat

Syntax-highlighting cat replacement for any source file:

```bash
ccat script.py           # Python with syntax highlighting
ccat main.c              # C with syntax highlighting
ccat config.yaml         # YAML with syntax highlighting
```

### hexyl — Binary Inspection

Colorized hex viewer for binary files:

```bash
hex /bin/ls              # colorized hex dump
hex firmware.bin         # binary inspection with color
```

## Firmware Updates (fwupd)

The `fwupd` service is enabled on all hosts for firmware updates via `fwupdmgr`:

```bash
# Check for available firmware updates
fwupdmgr get-updates

# Install updates
fwupdmgr update

# Show device firmware status
fwupdmgr get-devices
```

The `fwupd-refresh` timer runs periodically in the background to download the
latest firmware metadata from the [Linux Vendor Firmware Service (LVFS)](https://fwupd.org).

To disable automatic background refreshes:

```nix
# In your host configuration
systemd.timers.fwupd-refresh.enable = false;
```
